# Toloka — верификация событий на reasoning-трассах

Статический вьюер (GitHub Pages) для того, чтобы читать reasoning-трассу целиком и верифицировать
события, которые на ней нашли автоматические разметчики («агенты»): подтвердить, отклонить как
ложное или переразметить тип. По итогам считается score каждого агента.

Агенты: `regex` (детектор-регулярки), `Claude`, `DeepSeek` (chat/V3), `Qwen`,
`DeepSeek-R1` (reasoner-перепроход, срезы с инициалом R), `судья DeepSeek` (срез native-PO,
см. ниже). R1 виден на grid-трассах (имена `model__bench__qid`), где рядом есть DeepSeek-chat —
для адъюдикации R1 против chat.

Живёт на https://karpovilia.github.io/toloka/

## Как это работает

1. Слева — список трасс текущего опубликованного снимка. Точное число записано в
   `data/build_summary.json`. Открываешь трассу — она показана целиком, слева от текста
   «карта reasoning» (спаны + интенсивность λ по Хоксу + метки событий).
2. На каждом событии агентов — инлайн-контрол: ✓ подтвердить (реально это событие данного типа),
   ✗ отклонить (ложное срабатывание), либо выбрать другой тип. Событие = кластер срабатываний
   одного типа в окне ±1 сегмента; в скобках видно, какие агенты его нашли.
3. Выбираешь строку (клик по строке; клавиши `j`/`k` = перейти к след./пред. событию). Справа —
   инфа о ВЫБРАННОЙ строке: оператор спана (+что кодирует), λ, текст, ссылка на строку, и события
   на этой строке с кнопками ✓/✗/тип. Вердикт с клавиатуры — `1` да / `2` нет (первому событию
   строки); между трассами `[` / `]`. Кнопка «перейти к след. событию ▶» — в правой панели.
4. Сохраняешь результат: «экспорт» (файл) или «💾 GitHub» (коммит из браузера).
5. `python3 build/score_agents.py` считает score агентов.

Разметка живёт в localStorage браузера (ключ = candId `<trace_file>|s<seg>|<type>`).

## Реальность данных

Срез трассы = множество LLM-агентов, реально её разметивших (C = Claude, D = DeepSeek,
Q = Qwen, R = DeepSeek-R1; regex пересчитывается детектором на каждой трассе). Ключ трассы
канонизируется (`model`, `benchmark`, санитизированный `question_id`), поэтому одна и та же
трасса из разных каталогов разметки не двоится. Срезы корпуса на 2026-08: DQR 2093, CDQ 1684,
DQ 1080, CDQR 484, CD 356, DR 269, D 109, CDR 31 трасс; R1 покрывает 2877 трасс, из них
2577 размечены ещё и Qwen, 515 — ещё и Claude. Во вьюер уходит топ конфликтных сайтов
(cap 6000): пол в 300 сайтов каждому срезу, остаток — пропорционально числу LLM-vs-LLM
конфликтов (prio>=3), отбор внутри среза — round-robin по ячейкам модель×бенчмарк (иначе
кап срезал бы хвост алфавита: musique, qwen-модели). Покрыты все 5 бенчмарков (math500,
gpqa_diamond, hle, hotpotqa, musique) и все 3 модели. Событие с типом чужого домена (например
`branch` домена M на retrieval-трассе домена R) отбрасывается на сборке: вьюер его не
отрисует. Точные счётчики сборки — в `data/build_summary.json`.

## Срез native-PO: судья против регулярок на восьми моделях

Второй корпус вьюера, добавлен 2026-08-13. Восемь моделей четырёх семейств прошли один и тот же
набор вопросов в базовом плече свободного рассуждения (лимит 8192 токена, без принудительной
остановки), каждую трассу разметил судья `deepseek-chat` (события + операторные спаны), второй
слой — тот же канонический регулярочный детектор. Новизна по сравнению со старым корпусом:
срез мультимодельный, у каждой трассы указана модель-источник, поэтому расхождение слоёв
видно по моделям. Модели в фильтре — с префиксом `npo-`: gpt-oss-20b, gpt-oss-120b, Qwen3-8B,
Qwen3-4B, Qwen3.5-122B-A10B, R1-Distill-Qwen-7B, R1-Distill-Llama-8B, R1-Distill-Llama-70B.
Быстрый способ увидеть только этот срез — фильтр «агент» = `судья DeepSeek`.

В снимке 1022 трассы и 10103 конфликт-сайта: `type_mismatch` 2480 (сработали оба слоя, типы
разные), `judge_only` 4529 (кандидат в пропуск регулярок), `regex_only` 3094 (кандидат в
ложное срабатывание регулярок). По типам событий: subgoal_done 4639, backtrack 2832,
verify 2496, commit 2125, branch 1109, failed_attempt 330. Очередь адъюдикации упорядочена
по виду конфликта, а внутри вида — по силе расхождения слоёв между моделями: первым идёт
`backtrack`, где разброс плотности между моделями у регулярок x88.5 против x1.6 у судьи.

GPQA-diamond в этом срезе НЕ ПУБЛИКУЕТСЯ: репозиторий и Pages публичные, а доступ к
GPQA-diamond закрытый, поэтому 136 трасс по 17 вопросам этого бенчмарка исключены целиком —
ни текста вопроса, ни текста рассуждения. Остались MATH500 (472 трассы) и BBH (550),
оба публичные. Проверка запрета — `python3 build/check_no_gpqa.py`.

## Карта reasoning

Слева от текста — вертикальный гуттер на каждый сегмент (синхронный скролл):
- полоса оператора — операторный спан сегмента (SETUP/DERIVING/EXPLORING/VERIFYING/REVISING/
  CONCLUDING/GROUNDING) из dual-разметки (DeepSeek, если размечал трассу, иначе Qwen);
- красная полоса λ — измеренная интенсивность событий по Хоксу (ширина/яркость ∝ λ);
- глифы — события: ◇ branch, ◄ backtrack, ✗ failed_attempt, • прочие типы;
- клик по карте — попап с распределением λ по типам событий в этой точке (drill-down).

Интенсивность: `build/build_trace_maps.py` фитит пер-типовый self-exciting Hawkes (μ,α,β на тип,
ось = seg_id) на union-событиях корпуса; λ(s) = Σ_t λ_t(s). Параметры — в `data/trace_maps_meta.json`.
Быстрый пересчёт только λ — `--refit`. Данные карты — в `data/traces/*.json` (events/spans/lam).

## Скоринг агентов

`build/score_agents.py` по `annotations/annot_*.json`:
- gold по кандидату = мажоритарный вердикт разметчиков;
- detection precision агента = доля подтверждённых (✓ или переразмечен) среди размеченных
  кандидатов, где агент участвовал (± Wilson CI);
- type accuracy = доля верного типа (✓) среди реальных событий агента;
- межаннотаторное согласие: Cohen κ (2) / Fleiss κ (≥3).
- recall НЕ измеряется — пропущенные события в этой модели не размечаются (только события агентов).

## Сохранение результата

- Файлом: «экспорт» -> `annot_<ник>.json` -> в `annotations/` -> `git push`.
- Коммитом из браузера («💾 GitHub»): owner/repo/branch/path + fine-grained PAT (`contents:write`);
  файл `<path>/annot_<ник>.json` уходит в api.github.com. Работает с приватным репо. Токен — только
  в sessionStorage браузера до закрытия вкладки, в страницу не зашит. Ник аннотатора приводится
  к безопасному имени файла (`A-Za-z0-9._-`).

## Deep-link

`#trace=<trace_file>&seg=<N>` открывает конкретную трассу на событии; кнопка «🔗 ссылка» копирует URL.

## Сборка данных

    # По умолчанию REASONING_ROOT = родитель каталога toloka; можно переопределить.
    REASONING_ROOT=/path/to/reasoning python3 build/build_conflicts.py --cap 6000 --radius 12
    python3 build/build_trace_maps.py                          # события/спаны/λ в data/traces/*.json
    python3 build/build_nativepo.py                            # срез native-PO: судья против регулярок
    python3 build/build_traces_index.py                        # data/traces_index.json (список трасс)
    python3 build/validate_data.py                              # обязательная проверка согласованности
    python3 build/check_no_gpqa.py                              # запрет публикации GPQA в срезе native-PO

`build_conflicts.py` нормализует разные формы одного `question_id`, полностью обновляет
генерируемые trace-файлы и удаляет устаревшие файлы, которые больше не входят в выборку —
в том числе трассы среза native-PO, поэтому после него обязательны `build_nativepo.py` и
`build_traces_index.py`. `build_nativepo.py` идемпотентен: свои трассы и свои строки конфликтов
он переписывает целиком, а λ считает по параметрам Хокса, уже зафиксированным в
`data/trace_maps_meta.json`, чтобы шкала интенсивности была сравнима между корпусами и старые
трассы не переписывались. Для пересборки карты нужны `numpy` и `scipy`.

## Локальная проверка интерфейса

    npm install
    npm run check
    npm test

Версии Node соответствуют `engines` в `package.json` (LTS 20.19+ / 22.13+ и 24+).
Smoke-тест не содержит абсолютных путей и использует локальный `jsdom`. Минимальная
проверка данных без Node: `python3 build/validate_data.py`.

    build/                           сборщики · validate_data.py · score_agents.py · test_viewer_smoke.js
